## 5. Arquitectura recomendada para producción (100 → 5,000 usuarios)

### 5.1 Infraestructura actual lista
- **Backend:** FastAPI + SQLAlchemy + PostgreSQL.
- **Pool de conexiones:** `pool_size=10`, `max_overflow=20`, `pool_pre_ping=True`, `pool_recycle=1800`.
- **Índices:** ya agregados en `created_at`, `status`, `city`, `country`, `owner_id`.
- **Caché:** Redis opcional (`backend/app/cache.py`) para sesiones, rankings y resultados de búsqueda.
- **Frontend estático:** servido por `app/server.py` con proxy al backend.

### 5.2 Arquitectura objetivo para escalar a 5,000 usuarios concurrentes

```
┌─────────────────┐
│   Cloudflare    │  CDN + WAF + DDoS + DNS
│   (dominio)     │
└────────┬────────┘
         │
┌────────▼────────┐
│  Cloudflare     │  Tunnel / Load Balancer
│  Load Balancer  │
└────────┬────────┘
         │
┌────────▼──────────────────────────────┐
│  Kubernetes / Docker Compose          │
│  ┌─────────────┐    ┌─────────────┐  │
│  │ FastAPI     │    │ FastAPI     │  │  2-6 réplicas
│  │ API replica │    │ API replica │  │  (auto-scaling)
│  └─────────────┘    └─────────────┘  │
└─────────────────┬─────────────────────┘
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
┌────────┐   ┌─────────┐   ┌──────────┐
│PostgreSQL│   │  Redis  │   │  Celery  │
│Primary │   │ Cache   │   │ Workers  │
└────────┘   └─────────┘   └──────────┘
    │                           │
┌───▼───┐                  ┌────▼────┐
│Read   │                  │ RabbitMQ│
│Replica│                  │ / Redis │
└───────┘                  └─────────┘
```

### 5.3 Componentes clave

| Capa | Herramienta recomendada | Por qué |
|------|------------------------|---------|
| CDN + DNS + Seguridad | **Cloudflare** | Cacheo global, WAF, SSL, tunnels. |
| Contenedores / Orquestación | **Docker Compose** (ahora) → **Kubernetes** (producción) | Escalado horizontal, health checks. |
| Load balancer | **Cloudflare LB** o **Nginx Ingress** en K8s | Distribuye tráfico entre réplicas. |
| Base de datos | **PostgreSQL 15+** | ACID, full-text search, PostGIS para mapas. |
| Read replica | **PostgreSQL streaming replica** | Aliviar lecturas pesadas (rankings, búsquedas). |
| Caché / Sesiones / Pub-sub | **Redis** | TTL, rate limiting, WebSocket state, rankings. |
| Tareas asíncronas | **Celery + Redis/RabbitMQ** | Scraping de Facebook, procesamiento de imágenes, envío de notificaciones. |
| Almacenamiento de imágenes | **Cloudflare R2** o **AWS S3** | Escalable, barato, integrado con CDN. |
| Procesamiento de imágenes | **OpenCV / PIL + Celery** | Escaneo facial de perros, embeddings para matching. |
| Búsqueda vectorial | **pgvector** o **Pinecone** | Similaridad de imágenes de perros perdidos/encontrados. |
| WebSockets / Chat | **Socket.io** o **FastAPI WebSockets + Redis pub-sub** | Chat en tiempo real entre adoptante y refugio. |
| Monitoreo | **Sentry** (errores) + **Prometheus + Grafana** | Alertas, métricas, logs centralizados. |
| CI/CD | **GitHub Actions** → deploy a VPS/K8s | Tests, build, deploy automático. |

### 5.4 Escalado por etapas

| Etapa | Usuarios | Infraestructura |
|-------|----------|-----------------|
| 0 - Ahora | 0-100 | VPS único, Docker Compose, PostgreSQL + Redis local. |
| 1 | 100-1,000 | Separar DB en instancia dedicada, añadir Redis, Nginx reverse proxy. |
| 2 | 1,000-3,000 | 2+ réplicas FastAPI, Cloudflare R2 para imágenes, read replica PG, Celery workers. |
| 3 | 3,000-5,000+ | Kubernetes, auto-scaling, pgvector/Pinecone, CDN global, monitoreo completo. |

### 5.5 Buenas prácticas de backend ya aplicadas o recomendadas
- ✅ Paginación en todos los endpoints de lista.
- ✅ Índices en campos de filtro frecuentes.
- ✅ Connection pooling.
- ✅ Caché Redis opcional.
- ⬜ Añadir rate limiting (`slowapi` o Nginx).
- ⬜ Migraciones con Alembic.
- ⬜ Tests automatizados (pytest).
- ⬜ Logging estructurado (JSON).
- ⬜ Variables de entorno para credenciales.
- ⬜ Backups automáticos de PostgreSQL.

## 6. Notas para el diseñador / IA

- **No uses emojis** en los íconos finales; todo debe ser ilustración propia.
- **Mantén coherencia:** mismo grosor de línea, mismos colores, mismas proporciones.
- **Formato de entrega ideal:** PNG con fondo transparente + SVG editable.
- **Landing:** usa bordes redondeados (`border-radius: 24px`) en las imágenes, no máscaras circulares.
- **App móvil:** los íconos deben verse claros a 24×24 px y 48×48 px.
